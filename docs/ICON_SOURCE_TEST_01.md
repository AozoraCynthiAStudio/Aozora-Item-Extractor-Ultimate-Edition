# 图标来源选择测试 01

基于Performance Test 02，保持1.0.6测试版本，不更新正式Release。

## 本次实测证据

OG 1.10.163测试环境，Test02日志检测到1042条标签、1353条AutoTags规则。
AttachPack.esp 399条：首次请求到下一帧回执403.24ms、再次47.08ms；首次FIS聚合336.70ms。
Fallout4.esm 3431条：首次1490.81ms、再次95.95ms；首次FIS聚合1437.19ms。
这些是同一日志的测量，下一帧指标不是Present时间；用户评价略有压力但不大。
不能与另一AE/无FIS环境直接计算提升比例，不能证明所有大型插件都存在问题。

## 新增选择

MCM 外观分组 -> 物品图标（左右切档）：

- FIS 图标（默认）：维持原有解析，找不到时使用内置图标。
- 内置图标：跳过右栏与会话左栏的全部ResolveFISIcon调用；AS3不请求FIS图标库、不实例化FIS图标，使用现有内置图标。

下次打开菜单生效。更换来源时清除静态行缓存，避免沿用上一模式的图标元数据。
已经存在的FIS规则缓存和已加载库不强制销毁；内置模式不使用它们，沿用原有清理生命周期。
插件ESP/ESL图标、物品搜索范围与归属、数量、提取和归还行为不变。
未实施延迟图标、分页、并行扫描或新的资源生命周期。保留Test02的性能日志开关。

配置文件：`Data/MCM/Settings/AozoraItemExtractor.ini` 的 `[General] iItemIconSource=0` 为FIS，1为内置。
日志中 `ITEM_ICON_SOURCE mode=built-in` 可确认选择被读取；内置模式FISTotal calls应为0。

## 需要用户验证

1. 选内置，关闭并重新打开提取器；查看图标和首次进入耗时。
2. 切回FIS，重新打开；确认FIS恢复、缺失图标仍正常兜底。
3. 左栏会话图标、主题着色、分类、Take/Batch/Return行为保持正常。
4. 保存与读档后选择仍正确。

DLL/SWF编译及打包检查不等于游戏验收；新选项的实际提速仍待测试。
